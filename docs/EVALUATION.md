> 评估日期：2026-11-10（初评）/ 2026-11-13（补线上部署验证，见 §4.9）｜ 评估类型：**自测 + 可复现实验**（非第三方评审）

## 0. 结论先行

### 0.1 关键指标一览

| 指标 | 实测值 | 评价 |
|---|---|---|
| 二级结构折叠（1000 nt 上限） | 525.7 ms | 达标，接近宣称值（0.45 s） |
| 二级结构折叠（tRNA 76 nt） | 2.63 ms | 优于"秒级"预期两个数量级 |
| 配对概率矩阵 300 nt | 112.1 ms / 442 KB → gzip 3.8 KB | 达标，压缩率 99.1% |
| 3D 建模 500 nt | 196.9 ms / 3000 原子 | 达标 |
| 深度嵌入（76 nt，缓存命中） | 538 ms | 达标，但其中 434 ms 花在 PCA 上 |
| 深度嵌入（300 nt，缓存命中） | 1.89 s | **未达标**，用户会明显等待 |
| 后端测试 | 72 项 / 2.08 s 全通过 | 达标 |
| 前端测试 | 5 项 / 128 ms 全通过 | 覆盖偏薄 |
| 9 条示例与库内 dot-bracket/MFE | 9/9 完全一致 | 可复现性有证据 |
| 热力学自洽（eval 结构能量 = MFE） | 9/9 差值 0.0000 | 达标 |
| 3D 模型 Rg vs 实验结构（tRNA） | 29.9 Å vs 23.2 Å（+29%） | 诚实标注为拓扑级 |
| 首屏传输量（gzip） | 52 KB | 优秀 |
| 全量单点突变实验（tRNA，228 例） | 71% 引起 >5 对配对变化 | 关键解读性风险，见 §4.5 |

### 0.2 三个必须说清的短板

1. **深度层被 PCA 拖慢**：推理本身 0.3–2 s，但纯 Python 幂迭代 PCA 在 76 nt 就要 434 ms；300 nt 缓存命中仍要 1.89 s，时间主要消耗在 PCA 而非模型。这是当前唯一明显"用户能感到卡"的地方。
2. **没有外部真值基准**：所有"正确性"证据都是**内部自洽**（示例库由同一引擎生成、能量与结构互校）。没有跑标准二级结构数据集（如 RNAStrAlign / bpRNA），也没有把预测配对与 PDB 实验配对逐对比对。这决定了本报告的结论边界。
3. **单序列 MFE 对突变过于敏感**：228 例单点突变中 71% 引起超过 5 个碱基对的重新配对，容易被误读为"平台算错了"。这是 ViennaRNA 单序列折叠的固有特性，但产品需要主动解释。

### 1.2 方法

| 维度 | 做法 |
|---|---|
| 延迟 | 每个用例重复 5 次取**中位数**，同时记录最小/最大值；合成序列固定随机种子（GC≈50%） |
| HTTP 端到端 | FastAPI `TestClient`（进程内，无网络栈开销），覆盖全部端点与错误路径 |
| 深度层 | 区分"权重加载 / 未缓存推理 / 缓存命中"三段计时，并单独测量 `_pca2` |
| 3D | 建前主动删除对应缓存键，保证测到的是真实建模耗时；解析输出 PDB 计算碱基对距离、骨架间距、回旋半径 |
| 正确性 | ① ViennaRNA `eval_structure` 与返回 MFE 互校 ② 与示例库逐字符比对 ③ 括号平衡/最小环检查 ④ 拓扑（茎/发夹环）统计 ⑤ 228 例单点突变统计实验 ⑥ 与实验 PDB 的回旋半径对照 |
| 测试 | `pytest tests -q`、`node --test`、`npm run build` 实跑 |
| 体积 | 构建产物原始大小与 `gzip -c` 后大小 |

### 1.3 局限声明（影响结论外推）

- 全部数据来自**单机 CPU**，没有 GPU 对照；RNA-FM 在 GPU 上的延迟会显著不同。
- 合成序列只用于延迟测试，**不用于任何正确性结论**。
- 未在第二种操作系统（Linux/macOS）上复测；容器路径仅做了构建配置审查，未在本轮重新构建验证。
- 未做并发压测（单 worker 队列，压测意义有限），也未做长时间稳定性测试（>1 h）。
- 本文不是第三方评审，属于**自测报告**；所有原始输出的复现命令见附录 B。

## 3. 性能评估

### 3.1 折叠延迟与长度

| 长度 | 中位数 | 最小 / 最大 | 碱基对 | 相对 100 nt |
|---|---|---|---|---|
| 50 | 0.61 ms | 0.59 / 0.96 | 10 | 0.20× |
| 100 | 3.10 ms | 3.04 / 3.36 | 19 | 1.00× |
| 200 | 14.51 ms | 14.36 / 15.33 | 45 | 4.68× |
| 300 | 35.52 ms | 34.94 / 37.58 | 57 | 11.5× |
| 500 | 104.76 ms | 103.87 / 105.52 | 118 | 33.8× |
| 1000 | 525.68 ms | 522.99 / 558.75 | 267 | 169.6× |

**解读**：100 → 1000 nt 增长 169.6 倍，明显低于 O(n³) 的 1000 倍，高于 O(n²) 的 100 倍——符合 ViennaRNA 带剪枝的实际行为。1000 nt 约 0.53 s，说明"实时折叠"的限长设得合理；再往上（如 2000 nt）按此趋势会进入 4 s 量级，必须转异步，当前不做是正确取舍。

## 4. 正确性与一致性验证

> 这一节区分三种证据：**内部自洽**（强但只证明实现符合自身逻辑）、**可复现**（证明确定性）、**外部对照**（最弱，因为做得最少）。

### 4.1 热力学自洽：9/9 通过

用 `RNA.fold_compound(seq).eval_structure(predicted_structure)` 重新评估预测结构，与返回的 MFE 比对：

| 分子 | MFE | eval | 差 |
|---|---|---|---|
| 测试发夹 | −1.20 | −1.20 | 0.0000 |
| tRNA | −22.40 | −22.40 | 0.0000 |
| 5S rRNA | −50.90 | −50.90 | 0.0000 |
| 锤头核酶 | −8.10 | −8.10 | 0.0000 |
| HDV 核酶 | −33.60 | −33.60 | 0.0000 |
| TPP | −21.60 | −21.60 | 0.0000 |
| UUCG 四环 | −5.50 | −5.50 | 0.0000 |
| 长茎发夹 | −18.60 | −18.60 | 0.0000 |
| 双发夹 | −5.80 | −5.80 | 0.0000 |

说明接口返回的 MFE 与返回的结构是**同一套能量模型下的自洽结果**，不存在"结构是 A、能量报的是 B"。

### 4.2 可复现性

- 同一序列连续折叠 **20 次**，得到 **1 种**结构（完全确定）。
- 9 条示例折叠结果与 `examples.json` 中预存值逐字符一致、MFE 完全相等。
- 深度嵌入同一序列两次调用，640 维向量一致；PCA 在"首次计算 vs 缓存命中"之间存在 **≤0.001** 的差异（原因：缓存写入把向量量化到 3 位小数，见 §6）。

### 4.3 结构语法合法性

9 条预测结构全部：括号平衡、长度与序列一致、最小发夹环 ≥3 nt（实测 3–7 nt）。说明没有产生 ViennaRNA 语义下非法的结构，前端 dot-bracket 渲染不会出现越界。

### 4.4 拓扑对照（弱外部校验）

把预测结构拆成"茎 + 发夹环"：

| 分子 | 茎数（各茎 bp） | 发夹环 | 与已知拓扑的关系 |
|---|---|---|---|
| tRNA^Phe | 4（7/4/5/5） | 3 | 与经典三叶草一致：受体臂 + D 臂 + 反密码子臂 + T 臂 |
| 5S rRNA | 10（最长 10 bp） | 4 | 多茎环，量级合理 |
| HDV 核酶 | 7（最长 5 bp） | 2 | 双嵌套结构只部分恢复 |
| TPP 核糖开关 | 6（最长 4 bp） | 2 | 缺假结 |
| **锤头核酶** | **1（4 bp）** | **1** | **明显不足**：真实为三向连接，单序列 MFE 塌成一个 4 bp 发夹 |

**这是本报告最有价值的一条负面发现**：锤头核酶的预测结果（`..............((((....))))........`，仅 4 对）远低于其真实结构复杂度。原因是单序列 MFE 折叠不引入同源比对与三级接触约束——这不是本平台的 bug，而是"用 RNAfold 默认模式预测核酶"这件事本身的边界。Rfam 共识中 TPP 含假结标记（`[` 出现 5 次），而 MFE 预测永远不产出假结，两者对照时应在文档里说明，否则会被误解为"模型算错"。

### 4.5 突变语义实验：228 例单点突变

对 tRNA 的每个位点 × 3 种替换碱基（共 228 例）全部折叠，统计 ΔMFE 与配对变化：

| 位点类别 | 样本 | ΔMFE 均值 | 标准差 | 中位数 | 极值 | \|Δ\|<0.5 | Δ>+1 | Δ<−1 |
|---|---|---|---|---|---|---|---|---|
| 配对位点（位于茎区） | 126 | **+0.09** | 1.71 | +0.30 | −5.60 / +4.40 | 37% | 21% | 19% |
| 未配对位点（位于环区） | 102 | **−0.99** | 1.35 | −0.20 | −4.80 / +0.90 | 53% | **0%** | 36% |

补充统计：

- **228 例中有 161 例（71%）引起超过 5 个碱基对的重新配对**；平均断裂 9.2 对、平均新增 10.7 对。
- 最大去稳定：第 3 位 G→C，ΔMFE **+4.40**；最大稳定化：第 29 位 A→C，ΔMFE **−5.60**。

**三点解读**（都可写进答辩）：

1. **方向符合物理直觉**：茎区位点突变平均略微去稳定（+0.09），环区位点突变平均更稳定（−0.99）——因为环区本来不配对，换一个碱基更可能获得新的配对机会（环区突变 Δ>+1 的比例是 0%）。
2. **单点效应不局部**：71% 的突变导致大范围重排，说明单序列 MFE 的能量面很"崎岖"。这解释了为什么演示时把一个碱基换掉，右边整张结构图会变——**不是渲染错误**。
3. **产品风险**：如果不在 UI 上解释，评审很容易把"整条链重排"当成算法缺陷。建议在突变页加一句话："单序列 MFE 对突变敏感，ΔMFE 反映的是全局重折叠差异，不是局部扰动。"

### 4.6 3D 几何：约束满足 ≠ 物理精度

| 检验项 | 目标 | 实测（76/120/300/500 nt） | 结论 |
|---|---|---|---|
| 碱基对 P–P 距离 | 10.4 Å | 10.45–10.55 Å（最大 11.07） | 求解器收敛 |
| 相邻残基 P–P | 5.9 Å | 5.88–5.92 Å（区间 5.66–6.18） | 求解器收敛 |
| 原子数 | 6/残基 | 456 / 720 / 1800 / 3000 | 骨架完整 |
| 回旋半径 vs 实验 | 4TNA 23.2 Å | 模型 29.9 Å（+29%） | **偏大**，结构偏松散 |

必须说清：前两项是建模时**硬约束的目标值**，满足它们是自证，不能当作精度证据。唯一有独立意义的是 Rg 对照——模型比实验结构大 29%，说明它把分子摊得更开。因此"拓扑预览级"的定位是准确的，任何"接近实验精度"的说法都不成立。

实验结构 Rg 参考（P 原子）：4TNA 23.2 Å（62 原子）、1EHZ 22.9 Å、1DRZ 22.9 Å、1HMH 26.3 Å、2GDI 38.8 Å。

### 4.7 深度层

- 真实 RNA-FM 输出 **640 维**，与文档一致；降级路径 **34 维**，两者在 UI 上有明确区分标签。
- 冷启动加载权重 8.2 s（本地 SSD 热缓存）；README 记录的 19 s 是首次含冷盘/更大序列的情况，两者不矛盾，但**文档应写明"8–19 s 取决于磁盘与序列长度"**。
- 突变偏移实测（tRNA 第 7 位 U→A）：平均偏移 1.107、最大偏移 5.35、**最大偏移位点是第 66 位，而不是第 7 位**；Top5 = [66, 7, 6, 4, 8]。
  - 解释：RNA-FM 是上下文混合的表征，单点替换的影响会传播；Top5 里包含突变位点本身（第 2 位）。
  - 风险：页面上"受影响最大位点"如果被读成"突变位点"，就会引发质疑。建议加注："最大偏移不一定在突变位点，模型表征是上下文相关的。"

### 4.8 外部检索（RCSB）

- 5S rRNA（120 nt）检索：**3.7 s**，返回 5 条 ≥90% 相似结构（10QM / 11DG / 11EL，均为 E. coli 核糖体 EM 结构，分辨率 2.49–3.2 Å，得分为 1.0）。
- 第二次同序列调用：**0.0 ms**（LRU 命中）。
- 网络异常路径有测试覆盖（`test_tertiary_degrades_when_rcsb_unavailable`），降级为手动桥接。

**评价**：3.7 s 对交互来说偏慢，但只发生在"预置库未命中"的首次查询，且有明确的加载提示与取消按钮；缓存后无感。属于可接受的设计。

### 4.9 线上部署验证（2026-11-13 补测）

本地自测的说服力有个天花板：**"你的机器上能跑"不等于"别人点开就能用"**。因此补做一次远端验证——部署到托管沙箱后，用 HTTPS 直接打线上实例，不复用任何本地进程。

部署形态：单容器单进程、无持久盘；前端在安装阶段构建（`dist/` 不会随源码上传），启动命令读平台注入的 `PORT`。详见 `TECHNICAL.md` §9.3。

| 检查项 | 线上结果 | 与本地是否一致 |
|---|---|---|
| `/api/health` | `engine=viennarna-python`、`viennarna_version=2.7.0`、`rnafold_available=true` | 一致（云端 wheel 正常安装） |
| `/api/fold` tRNA 76 nt | `mfe=-22.4`、`num_pairs=21` | 一致，dot-bracket 逐字符相同 |
| `/api/pairprob` 9 nt | `engine=viennarna-bpp` | 一致（走配分函数，非采样） |
| `/api/3d/predict` 76 nt | `engine=builtin`、`atoms=456` | 一致 |
| `/api/examples` | 9 条 | 一致 |
| 前端路由 `/` `/fold` `/mutate` `/deep` `/tertiary` | 均 HTTP 200，`<title>` 正确 | — |
| 静态资源 | `/assets/index-*.js` 200 | — |
| 深度层（预置示例） | `source=cache`，640 维，秒级 | 一致（命中随包上传的 `data/cache`） |
| 深度层（全新 40 nt 序列） | 失败 → `engine=fallback`、34 维，约 12–20 s | 本地为真实 640 维 |

> 降级原因值得写清楚：实例**没有安装深度依赖**（torch / transformers），权重也不在包内。两次实测的报错不同——一次是加载时 `OSError: ... 503`（镜像不可达），一次是 `AttributeError: 'NoneType' object has no attribute 'from_pretrained'`（transformers 缺失），但结果都落到同一个 34 维降级路径。这说明降级链本身是可靠的，但也说明**主引擎可用 ≠ 深度层可用**。

**结论**：核心链路（折叠 / 配对概率 / 3D / 示例库 / SPA 路由）在云端与本地**逐项一致**，说明"能在你机器上跑"这件事可以外推。**深度层不能外推**——沙箱没装 torch、权重也不在包里，预置示例靠缓存"看起来正常"，新序列会降级；这正好暴露一个设计上的隐患：**缓存让降级变得不易察觉**，页面上虽有 `source` 标签，但非专业用户不会注意。

**新增缺陷（本次补测发现）**：

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| M7 | 部署环境缺少深度依赖时，预置示例仍显示 640 维（来自缓存），与"新序列降级"并存，状态不一致 | 评审若先点示例再粘新序列，会看到两套维度 | 在深度页顶部常驻"当前实例深度引擎状态"；缓存命中时同时标注"该向量由 X 环境预计算" |

| L7 | `dist/` 属构建产物、不随源码上传 | 直接照搬 Docker 流程部署会得到 404 首页 | 已在 README / TECHNICAL §9.3 写明安装阶段构建 |

**缺口**：前端只有 `sequence.js` 有单测，5 个页面组件零测试；没有 E2E（表单 → 折叠 → 图表渲染这条主链路只靠人工验证）。

### 5.2 CI

`.github/workflows/ci.yml` 两个 job：后端（Python 3.11 + pytest）、前端（Node 18 + npm ci + npm test + build）。ViennaRNA 安装失败时用 `|| echo` 容忍降级，所以 **CI 绿不代表真实引擎可用**——这是刻意的取舍，代价是必须在本地/容器另做一次真引擎验证（本报告 §4.1 就是这个验证）。

### 5.3 错误处理（实测矩阵）

| 输入 | 状态码 | 文案 |
|---|---|---|
| `ACGTN` | 400 | 含简并碱基 N，无法预测结构；请展开为 A/U/C/G |
| 空串 | 400 | 序列为空：请粘贴 A/U/C/G 序列或 FASTA 记录 |
| 1001 nt | 400 | 序列长度 1001 nt 超过实时折叠限长 1000 nt |
| 突变位点 999 | 400 | 突变位点超出序列范围 |
| 非法 model id | 404 | — |
| 未知非 api 路径 | 200 | 返回 SPA index（前端渲染 404 页） |
| 未知 api 路径 | 404 | 接口不存在 |

错误文案都带**可执行的下一步**（"请展开为 A/U/C/G"），不是裸的 "invalid input"。这一点在同类课程项目里不常见。

### 5.4 安全与部署

- CORS 默认 `*` 但可配置；限流 30 次/分/IP 只作用于会出网的 `/api/tertiary`；`RNA_TRUST_PROXY` 默认关闭（防止伪造 `X-Forwarded-For` 绕过限流）。
- 静态托管有 `realpath` 越界校验；PDB ID 限 4 位字母数字、模型 ID 限 40 位 hex。
- 容器：多阶段构建、非 root（uid 10001）、`HEALTHCHECK`、缓存写命名卷、`stop_grace_period: 30s` + lifespan 取消长任务。
- **无鉴权**：定位是单机/内网工具，公网部署需自行加反代与认证。这是范围选择，但必须在交付说明里写明。
- **线上演示实例**：访问控制由托管平台的分享链接承担（首次带 `?sharecode=` 种 `__wb_rsc` cookie，之后同源请求免参数），不是应用自身的账号体系；实例单进程、无持久盘，仅用于评审查看，不作为生产服务对外承诺。

### 5.5 可复现性

- 依赖全部锁版本（`fastapi==0.128.8`、`ViennaRNA==2.7.0`、`transformers==4.46.3`、`multimolecule==0.0.8`），并注释了"为什么不能升级"（§3.3 的两个坑）。
- `run.sh` / `run.bat` 一条命令完成环境、依赖、构建、启动；README 记录干净克隆实测 3 分 20 秒（缓存命中）/ 约 9 分钟（含下载）。
- 镜像可写入 `GIT_COMMIT`，便于追溯。

**缺口**：没有 lockfile 级别的完全复现（Python 侧只锁直接依赖，未用 `pip freeze` 锁传递依赖）；RNA-FM 权重需手动下载，首次从镜像拉取受网络影响。
